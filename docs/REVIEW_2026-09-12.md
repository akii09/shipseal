# Shipseal review: gaps against the vision

> Reviewed 2026-09-12 against `docs/PROJECT_PLAN.md`, the repo at `main` (v0.0.6), the published npm package, and shipseal.dev.
> Place at `docs/REVIEW_2026-09-12.md`. Each item has an ID so agents can reference it in commits (`fix(G3): ...`).

## Verdict

The engineering is ahead of what was pitched. Phases 1 to 3 are built in about 7,300 lines: provenance manifest, number guard, fitting, brand detection (Tailwind, CSS vars, DTCG), composite Action, golden tests, dogfooded releases, a clear docs site, and an agent page. The core promise ("every number verified") is real and demonstrable.

The gaps are not in the code. They are in **what the cards say, how they look, and who has seen them**. The product's own showcase currently undersells it. Fix the P0 items before any public launch.

---

## P0: fix before launch

### G1. The showcase headline is internal bug-fix language
The hero on the README and the homepage says "Never put a truncated headline on a card". To a visitor this reads as a strange instruction, not a release. It is a maintainer's fix note from v0.0.6. The first card anyone sees is the product's pitch, and right now it is a patch note.

**Fix:** cut a minor release with a real, user-facing feature (for example milestone cards or light theme) and regenerate the showcase from that. Keep the showcase honest (generated, unedited), but choose a release worth showing.

### G2. No release-significance awareness
`copy/deterministic.ts` falls back to fixes for the headline (`[...breaking, ...features, ...fixes]`). A patch release with only fixes produces a hero card whose headline is a bug fix. Nobody posts that.

**Fix:**
- Derive `release.kind` (major, minor, patch) from semver of the tag vs previous tag, with provenance.
- Add `release.announce` config: `"minor"` default. Below the threshold, skip hero cards and optionally render a compact "N fixes in vX" card, where N is a counted fact.
- Never use a fix as the hero headline unless the user opts in.

### G3. Changelog lines are written for maintainers, not audiences
Even feature entries read like commit messages ("Do not use a private workspace root's name as the project name"). Deterministic copy cannot turn that into a headline.

**Fix (cheap, deterministic, keeps R1):**
- `--headline "..."` and `--subheadline "..."` flags, and `release.headline` in config. Provenance: `user-config`.
- Support a marker in release notes or changelog: `<!-- shipseal: headline "Milestone cards are here" -->`.
- Document this as the recommended path; position the optional LLM as the "rewrite for humans" step, which is exactly where it earns its place.

### G4. Site claims that are not true yet (bad look for a "verified" product)
- "One command, one folder, **eight images**", but the listed tree shows six images plus the manifest.
- The tree shows `og.png`, `x.png`, `code.png`, but real output names are `release-hero-og.png`, `code-card-x.png`, and so on.
- "Plus square, portrait, Product Hunt and README banner sizes": these exist in `formats.ts`, but **no template supports them** (templates declare only og, github-social, x, linkedin).

**Fix:** make the site tree match a real `ls` of a real pack (generate it in CI like the showcase), state the real image count, and change the sizes line to "coming soon" or remove it. Add a CI check that fails if the homepage tree diverges from actual output.

### G5. Zero external users
npm shows v0.0.4 to v0.0.6, 1 star, and the downloads API does not return data yet. The plan's Phase 4 criterion is "at least 3 external repos use the Action before launch day." Since the validation gate was removed (§25, a fair call), this criterion is now the only demand check left. Keep it.

**Fix:** before Show HN or Product Hunt, personally onboard 3 to 5 repos (PDFx first, then maintainers you know). Open PRs adding the workflow for them. Record each in `docs/adopters.md` with what broke.

## P1: makes it memorable

### G6. Milestone and benchmark cards are invisible
Both are built (`milestone.tsx`, `bench.tsx`) but not shown in the README or on the site. Milestone cards are the most shareable output in the whole product.

**Fix:** add a real milestone card to the README and homepage. PDFx has 1,000+ stars, a real number with a real source, which is a perfect verified demo. Add a bench card from a real Shipseal or PDFx benchmark.

### G7. Cards look tidy but generic
The hero is well set text on black with the right half empty. The code card draws a 14-line box for a 2-line snippet, leaving most of the card empty with small type. Nothing on the cards says "this is Shipseal" except a footer.

**Fix:**
- Size the code box to its content, and scale the font up for short snippets (fitting logic already exists).
- Use the empty right side of the hero: a large faded logo, a subtle brand-colored gradient or grid, or the "sealed" motif below.
- **Signature element:** a small seal stamp on each card with verified facts, for example `sealed · 7 commits · 2026-09-11`. It turns the core promise into a visible brand mark and makes cards recognizable in a feed. It must follow R1 (all values from facts).
- Show a light-theme example somewhere; the site only shows dark.
- Raise contrast on the version badge (red text on dark grey is weak).

### G8. Code card snippet does not match the headline
The v0.0.6 code card pairs a bug-fix headline with the README install commands. The snippet should relate to the headline.

**Fix:** snippet priority: a code block inside the changelog entry used for the headline, then `release.snippet` config, then README. When the snippet is only install commands, title it "Get started" rather than reusing the release headline.

### G9. npm CTA not detected in the monorepo
The hero CTA shows `github.com/akii09/shipseal` although `shipseal` is on npm. The root package is private and the published package lives in `packages/shipseal`.

**Fix:** when the root is private, look for a single public workspace package (or honor `--package`) for `npmPackage`, and verify it exists on the registry before using `npm i <name>` as the CTA.
